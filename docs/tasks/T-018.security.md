# Security review T-018 — FINDINGS
Boundary: B6  Risk class: medium

1. [MEDIUM] `SecClient` interpolates untrusted EDGAR JSON fields directly into follow-up request
   URLs with no format check. `_document_url()` (fathom/live/sec.py) builds
   `.../Archives/edgar/data/<cik>/<accession-no-dashes>/<primary_document>` from
   `entry["accessionNumber"]` and `entry["primaryDocument"]`, and `filings()`'s older-pages loop
   builds `_SUBMISSIONS_PAGE_URL.format(name=name)` from `page.get("name")` — both values come
   from the `submissions` JSON already fetched over the boundary and are not validated against
   `^\d{10}-\d{2}-\d{6}$` (accession) or a safe filename pattern (primary_document/name) before
   being placed in a URL. `SecFiling.accession`/`primary_document` (Pydantic) are plain `str`
   with no pattern constraint either. Under boundary B6's threat T (tampered/malformed JSON), a
   compromised or malformed response can steer subsequent GETs to unintended paths under
   www.sec.gov (host stays fixed, so this is not host-redirection/SSRF) and can manipulate the
   `sha256(url)` cache key — control C-09 — fix required before merge: validate `accession`
   against the frozen pattern and `primary_document`/`name` against a safe-filename pattern
   (reject `/`, `..`, control chars) in `_to_filing`/`filings()` before constructing any URL, or
   accept explicitly if a downstream task (T-019/T-020) is confirmed to add this gate before
   `sec.py` output reaches materialization.

2. [MEDIUM] `LiveHttp.get()` (fathom/live/http.py) calls `self._client.get(url, headers=...)`
   without `stream=True`; the size check (`len(body) > _MAX_BODY_BYTES`, ~line 78) runs only
   after `response.content` has already buffered the entire body in memory. This satisfies the
   letter of "check length before `.text`/decode" (decode happens later in `sec.py`) but not the
   design's stated mitigation for boundary B6 threat T/D — "size caps 25 MB per document" — since
   an outsized or malicious response is fully downloaded before it is rejected, allowing memory
   exhaustion from a single oversized response (no host compromise required, just an
   unexpectedly large or adversarial body) — control C-09 — fix required before merge (stream the
   response and enforce the cap incrementally), or accepted candidate if the team judges the
   current SEC/Yahoo/Stooq endpoints low-risk for this specific vector — should be noted
   explicitly if accepted, since `LiveHttp` is shared by future `PriceClient`/`facts.py` callers.

3. [LOW] `SOURCE_HTTP` details on transport failure carry `"reason": str(exc)` (fathom/live/http.py,
   `httpx.HTTPError` branch). `str()` on an `httpx.HTTPError` typically includes the request URL.
   No secrets exist in current SEC/Yahoo/Stooq URLs (public tickers/CIKs only), so this does not
   leak anything today, but it means the "no secrets in error details" property depends on every
   future caller of `LiveHttp` never putting sensitive data in a URL, not on the error-construction
   code itself — control C-12 — accepted candidate; revisit if a keyed provider (out of scope per
   FR list) is ever wired through this same path.
