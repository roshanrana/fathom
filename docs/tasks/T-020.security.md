# Security review T-020 — FINDINGS
Boundary: B1, B6  Risk class: medium

1. [HIGH] Free-text ticker input from every B1 surface (page `st.text_input` in `app/main.py`,
   `fathom fetch`/`quote`/`filings`/`brief`/`ask` in `fathom/cli.py`, the API path/query
   `ticker` in `fathom/api.py`, and the MCP tool `ticker` args in `fathom/mcp_server.py`) reaches
   `fathom/live/build.py::materialize()` — `symbol = ticker.upper()` then
   `live_dir = settings.live_cache_dir / symbol`, `manifest_path = live_dir / "manifest.json"`
   — with no call to `require_ticker`/`_LIVE_TICKER_RE` (`^[A-Z][A-Z0-9.\-]{0,9}$`) anywhere in
   `fathom/live/__init__.py::data_dir_for` or `build.py` before that path is built. A ticker like
   `..` or `../x` therefore reaches `Path(live_cache_dir) / ticker` unvalidated:
   `_read_fresh_manifest()` unconditionally does `manifest_path.exists()` + JSON-parses whatever
   is there for *any* traversed path before any SEC lookup runs, and (once `sec.lookup(symbol)`
   succeeds) the same unvalidated `symbol` is reused for `live_dir.mkdir(parents=True,
   exist_ok=True)` and the four `.to_parquet()` writes. `SecClient.lookup`'s exact-membership
   check against SEC's ticker map happens to gate the write side today, but that is incidental
   protection, not the validation this task was supposed to add — `05-m4-live-data.md` §5
   explicitly specifies `require_ticker(ticker, settings)` for this purpose, and T-019's review
   (`docs/tasks/T-019.security.md` finding 3) flagged that `PriceClient`/`facts.snapshot` rely on
   "an as-yet-unwritten caller" (this task) to validate first — `build.py` still doesn't. Every
   call site that reaches `require_ticker` (`briefing.py:159`, `data.py:74`, `filings.py:367`,
   `quotes.py:144`) calls it as `require_ticker(ticker)` with no `settings` argument, so even
   downstream the live-mode regex path is never exercised — control C-09 — fix required before
   merge: validate the upper-cased ticker against `_LIVE_TICKER_RE` in `materialize()` (or in
   `data_dir_for`) before any path is constructed, on every surface.

2. [MEDIUM] `fathom/api.py`'s `_STATUS_BY_CODE` (unchanged by this diff) maps only
   `UNKNOWN_TICKER`/`PROVIDER_CONFIG`/`PROVIDER_HTTP`/`PROVIDER_TIMEOUT`/`CONTRACT_INVALID`. The
   M4 codes `Code.SOURCE_CONFIG`/`SOURCE_HTTP`/`SOURCE_EMPTY` (raised by `materialize()` on every
   `?source=live` request path) are not in the map, so `_fathom_error_handler` falls through to
   the generic 500 `INTERNAL` body instead of the 502/503 `05-m4-live-data.md` §5 calls for. No
   internals actually leak (the 500 body is the same generic `{"code":"INTERNAL", ...}` used for
   unmapped/unexpected errors, satisfying C-12's "generic 500" rule) but the specific
   `SOURCE_CONFIG`/`SOURCE_HTTP`/`SOURCE_EMPTY` signal is lost to every API caller (page/API
   client), which is the surface-parity gap the design calls out — control C-12 — fix required
   before merge: add the three `SOURCE_*` codes to `_STATUS_BY_CODE` (502 for `SOURCE_HTTP`, 503
   for `SOURCE_CONFIG`/`SOURCE_EMPTY` per the task's own mapping).
