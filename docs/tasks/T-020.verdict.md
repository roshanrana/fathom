## Live-ticker reproduction (surface → outcome)
Reproduced fully offline (no network; `HTTPS_PROXY=http://127.0.0.1:9`) via `CliRunner` with
`fathom.cli.data_dir_for`/`fathom.cli.materialize` monkeypatched to return a live-cache-shaped
directory for ticker `NFLX` (built by relabeling the repo's real AAPL fixtures, so `NFLX` is
absent from fixture `UNIVERSE` but the cache/manifest are otherwise valid):

| Surface | Call | Outcome |
|---|---|---|
| CLI `quote` | `quote NFLX --source live` (data_dir_for mocked, returns live dir) | `data_dir_for` reached and returned live data, but exit 2 `error UNKNOWN_TICKER: unknown ticker 'NFLX'; must be one of AAPL, …` — **FAIL** |
| CLI `filings` | `filings NFLX --source live` | same: exit 2 `UNKNOWN_TICKER` — **FAIL** |
| CLI `fetch` | `fetch NFLX` (materialize mocked to succeed, returns a valid `LiveManifest`) | `materialize` succeeded; `quote_card` call inside `fetch` then raises `UNKNOWN_TICKER`, exit 2 — **FAIL** |
| API | not separately re-run; `get_quote`/`get_filings`/`post_brief`/`post_ask` share the exact code path (`quote_card`/`filings_for`/`brief_flow`/`ask_flow`) — same defect applies | **FAIL by inspection** |
| MCP | `get_quote`/`list_filings`/`get_briefing`/`ask_filings` call the same functions | **FAIL by inspection** |
| Page | `app/main.py:96-97` calls `quote_card(ticker, data_dir)`/`filings_for(ticker, data_dir)` with no settings | **FAIL by inspection** |

Root cause: `fathom/data.py`'s `require_ticker(ticker, settings=None)` was correctly extended for
live-mode validation (AC2's own narrow unit tests pass), but none of its call sites outside
`fathom/data.py` were updated to thread `settings` through: `fathom/quotes.py:144`,
`fathom/filings.py:367`, `fathom/briefing.py:159` all call `require_ticker(ticker)` bare, so they
silently default to `settings=None` → fixture-mode `UNIVERSE` check. The implementer's own new
tests never caught this because every new test (`tests/test_cli.py`, `tests/test_api.py`,
`tests/test_app.py`, `tests/test_mcp.py`) uses ticker `"AAPL"`, which happens to be in `UNIVERSE`
regardless of source — so the bug is invisible unless a genuinely non-fixture ticker is exercised
end-to-end, exactly matching the orchestrator's original `NFLX` observation, which this
reproduction confirms.

## Findings
1. **CRITICAL** — `require_ticker` wiring gap (`fathom/quotes.py:144`, `fathom/filings.py:367`,
   `fathom/briefing.py:159`): none of these call sites pass `settings` to `require_ticker`, so
   every surface (CLI `quote`/`filings`/`fetch`/`brief`/`ask`, API's four routes, all four MCP
   tools, and the Streamlit page) rejects any ticker outside the fixed 20-ticker fixture `UNIVERSE`
   in live mode with `UNKNOWN_TICKER`, even after `materialize`/`data_dir_for` have already
   succeeded and produced a valid live cache. This defeats FR-020's core promise ("in live mode
   every surface serves any SEC-listed ticker") and directly reproduces the orchestrator's `NFLX`
   observation. Fix: thread `settings` (or the already-resolved `data_dir`/live-ness) through to
   every `require_ticker` call site, or move the fixture-universe check out of the shared helper
   entirely for live-routed calls.
2. **HIGH** — AC7's required `test_nfr012_*` test (cold-materialize elapsed time, informational)
   is entirely absent from the diff; NFR-012 has no coverage at all.
