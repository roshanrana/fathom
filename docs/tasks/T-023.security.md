1. [HIGH] `PriceClient._yahoo`/`_bars_from_yahoo` (fathom/live/prices.py) call `.get()` on
   `result` (`chart.result[0]`) and on `result.get("indicators")` with no dict-type check first.
   When Yahoo returns a plausible malformed shape where `result` or `indicators` is a non-dict
   truthy value (e.g. an error string in place of the expected object — `result[0]` on a string
   succeeds via char-indexing, so it passes the `cast()`, which is type-checker-only), `.get()`
   raises `AttributeError`. `_PARSE_GUARD_EXCEPTIONS` does not include `AttributeError`, so it
   escapes `_yahoo()` and `daily_bars()` uncaught (confirmed via direct repro:
   `{"chart": {"result": "oops"}}` and `{"chart": {"result": [{"indicators": "garbage", ...}]}}`).
   Confirmed with Stooq primed to serve valid bars in the same call: the documented
   Yahoo→Stooq fallback is skipped entirely rather than attempted — the same failure mode T-019
   F1 targeted, via an exception type the guard tuple omits — control C-09 — fix required before
   merge (add `AttributeError` to `_PARSE_GUARD_EXCEPTIONS`, or validate `isinstance(result, dict)`
   / `isinstance(indicators, dict)` before use).
2. [HIGH] `_TICKER_RE` (fathom/live/prices.py) and `_CIK_RE` (fathom/live/facts.py) anchor their
   pattern with `$`. Python's `$` matches at end-of-string *or* immediately before one trailing
   `\n`, so `"AAPL\n"` and `"0000320193\n"` both satisfy `_TICKER_RE.match`/`_CIK_RE.match` and
   pass validation. The trailing `\n` then reaches the Yahoo/Stooq/SEC URL template, and `httpx`
   raises `InvalidURL` while constructing the request — `InvalidURL`'s MRO is
   `(InvalidURL, Exception, BaseException, object)`, i.e. not a subclass of `httpx.HTTPError`, so
   `LiveHttp.get()`'s `except httpx.HTTPError` does not catch it and it is not a `FathomError`.
   Confirmed end-to-end: `PriceClient.daily_bars("AAPL\n")` and
   `facts.snapshot(sec, "0000320193\n", ...)` both raise uncaught `httpx.InvalidURL` with 0
   transport calls made. This is an incomplete fix for T-019 F3: the identifier is validated,
   but the validation itself is bypassable and the failure mode on bypass is an uncaught
   non-`FathomError` exception rather than the intended pre-request rejection — control C-09 —
   fix required before merge (anchor both patterns with `\Z` instead of `$`, or use
   `re.fullmatch`).

Checks confirmed clear (no finding beyond the above): no filing/response body or URL text
appears in any `FathomError` message/`details` in either file, nor in the two uncaught
exceptions' own text (`httpx.InvalidURL`'s message names only the offending character and
position, not the full URL; the `AttributeError` message names only the Python type, not any
response content) — consistent with C-12; no new dependency (`git show HEAD --stat` touches only
`fathom/live/{prices,facts}.py`, `tests/test_live_{prices,facts}.py`, and a task doc — no
`pyproject.toml`/`uv.lock`); no signature changes to `PriceClient.daily_bars` or
`facts.snapshot`; `sec.py`'s CIK path and `prices.py`'s ticker path are otherwise correctly
rejected pre-request for every other malformed/malicious shape tried (SQL-injection-shaped,
path-traversal-shaped, oversized, NUL-byte, non-ASCII, embedded-newline-with-trailing-text).

   all the way to the pipeline entry point. This is the same root defect class as HIGH-1
   (an unguarded exception type breaks the Yahoo→Stooq fallback contract and surfaces a

   No sensitive data leaks in either exception's message (platform-generic text only) —

   `OSError` and `OverflowError` to `_PARSE_GUARD_EXCEPTIONS`, or bounds-check `ts` before
