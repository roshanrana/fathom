# Security review T-009 — FINDINGS
Boundary: B1 (B2, B4 touched)  Risk class: medium

1. [MEDIUM] `run_api` (fathom/cli.py, `uvicorn.run("fathom.api:create_app", factory=True,
   host="0.0.0.0", port=port)`) binds the HTTP API to all interfaces by default with no
   `--host` option to narrow it. Threat model B1 documents "no identity in the prototype ...
   hosting requires SSO in front (C-08)" as an accepted gap for a *local* demo; a default
   0.0.0.0 bind turns that into an unauthenticated surface reachable from any network the host
   is on, not just localhost. Fix required before merge (or explicitly re-accept in the threat
   model): default `host="127.0.0.1"`, with `0.0.0.0` opt-in via a flag/env var if remote demo
   access is ever needed.

2. [LOW] `AskBody.question` (fathom/api.py) and the CLI `ask` argument (fathom/cli.py) accept
   an unbounded `str` — no `max_length`, unlike `Claim.text`/`quote` in fathom/contracts.py
   which are capped (600/2000 chars). Nothing downstream truncates before the question reaches
   `guard.is_advice`, BM25 retrieval, and the provider prompt, so an arbitrarily large body
   inflates prompt size/cost and is an easy DoS lever against B1's "large or repeated requests"
   row (documented as accepted at low likelihood/impact, but that entry assumes bounded input).
   Recommend adding `Field(max_length=...)` to `AskBody.question` (e.g. a few thousand chars)
   — accepted candidate for now, not blocking.
