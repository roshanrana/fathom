## Findings

1. **CRITICAL / BLOCKING — heading-vocabulary fallback selects wrong or contaminated bodies for
   4 of 10 changed real 10-Ks** (CAT `10-K:3`, CVX `10-K:7`, XOM `10-K:7`, JPM `10-K:7`; see
   spot-check table for exact evidence and offsets). This is exactly the failure mode the task
   pack calls out as blocking ("a wrong heading match that captures unrelated text"). The
   automated regression test does not catch this because it only asserts the new body is ≥ 400
   chars, never that it is the *correct* section's content. Must be fixed before this task can
   ship: the candidate-selection heuristic needs either (a) a real heading detector (indentation,
   whitespace-only line, page-break markers, or dedup of repeated running headers) instead of
   "any line whose stripped text starts with the phrase," and/or (b) a size sanity cap / better
   tie-break than "always take the longest candidate."

2. **HIGH — AMZN `10-K:3` and TSLA `10-K:3` bodies are contaminated (not blocking) by boundary
   overrun** into Items 4–8 content because no `Item N.` header is detected between the true
   heading and the next heading-vocab match. Same root cause as finding 1, lower severity because
   the start of the body is at least correct.

3. **HIGH — the 10-Q side of the fallback never actually fires when a 10-Q id shares a title key
   with a 10-K id** (`10-Q:I.2`/`10-K:7`, `10-Q:I.3`/`10-K:7A`, `10-Q:I.4`/`10-K:9A`,
   `10-Q:II.1`/`10-K:3`, `10-Q:II.1A`/`10-K:1A`). `_TITLE_KEYS` is a single dict and
   `_heading_vocabulary_matches` assigns each heading line to the *first* matching `section_id` in

   silently fails to widen. This never manifests against the current 97-fixture set (verified: no
   10-Q fixture needed the fallback), so it does not affect AC2 today, but it is a genuine spec
   gap against LLD §2.5 step 7's explicit "10-Q ids: the same keys for the matching titles"
   clause and will silently under-perform the first time a real 10-Q needs it.

4. **LOW — MCD `10-K:3`'s new body likely runs a few hundred characters past the true Item 3
   boundary into the auditor's signature block** (see spot-check table). Non-blocking: AC1 only
